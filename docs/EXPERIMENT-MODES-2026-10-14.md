# Champions M-C 検証モードと数字の解釈（2026-10-14）

## 旧：固定3体ストレス試験（研究用の例外条件）

- `lab.js` / `optimize.js` は、実際の相手3体と先発を検証側で指定する。
- 対戦する候補AIは相手公開6種から選出するが、従来の規則では同じ見せ合いなら決定論的に同じ3体となる。
- Showdownが処理するのはゲーム状態、技の成否・乱数・効果・合法な手番など。**相手やこちらの合理的な3体選出はShowdownの対戦エンジンが自動で考案するわけではない。**
- `reports/five-cycle-50000-2026-10-14.md` の0/250、250/250、E案65.3%はこの特殊条件のAI間スコア。実ランク戦勝率や構築全体の強さを示さない。

## 新：双方独立の6見せ3出し試験

- `preview-opponents.js` が8種類の異なる相手6体を定義。実戦使用率を再現する分布ではなく、対戦機構検証用。
- `optimize-preview.js` は `game(..., scenario=null, ..., {previewPolicy:'stochastic'})` を使用し、両サイドとも実際の選出3体・先発を検証側で固定しない。
- `preview-policy.js` は各サイドに**自分の6体・相手の公開6種だけ**を渡して20通りを評価。攻防補完の評価値に応じた上位の有望3体を重み付きで選び、先発も候補から重み付きで選ぶ。劣後した全20通りからの完全ランダム選出ではない。
- 相手の未公開3体・持ち物・技・能力ポイントは、AIの選出判断に渡さない。自分のチームの6体は当然分かっている。
- Showdownの対戦乱数とAI独自の選出用乱数は別の擬似乱数系列。シードは再現可能。同じ候補比較で相手公開6体、試合シード、左右席順を合わせているが、**行動経路の違いから乱数消費は変わり得る**。
- 対戦CSVには両サイドの実選出3体・先発・勝敗・試合シード・入力エラー件数を出力。summaryには相手6体ごとの選出パターン頻度を記録する。
- 旧固定ストレス試験は残し、全体評価と混同しない。

- どちらも**ランク戦の実戦勝率やチャンピオン級の到達確率を表すものではない**。

## 残る本質的な課題

1. 相手の型分布や選出戦略の頻度は公開データに基づいておらず、上位ランクに近いとは断定できない。
2. 複数の近接選出の確率的な選択は実装したが、手番の技・交代AIはまだ粗いヒューリスティック中心。対人上級者級ではない。
3. 勝ち筋や被弾、スピード・技の読み、相手の6から想定される3体の分布の校正が必要。
4. 試合数を増やしても、未実装の戦略知識や環境分布は自動で補完されない。
