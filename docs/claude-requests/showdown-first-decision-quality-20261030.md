## 優先タスク：実現可能な最小実装で「対戦AIの合理性」を直接改善する
1. まず既存 `lab.js` の`Bot.decide(req)` と外部`decision-v2.js`の接合可能性、公開情報の境界を精査。実装は**旧AIのデフォルトを変更しない新しい候補policy**（`decisionPolicy:'lookahead'`等）としたうえで、常識的な対戦の欠陥を**再現可能な回帰テスト**で潰す。過大なリファクタリングは不要。
2. 最優先の具体的な合理性ガード：**(i)** ガア等の物理受け/はねやすめ+ゴツメに接触技5連打で自滅しない **(ii)** こだわり技ロックで相手無効/耐性なのに居座らず、合法な交代を優先 **(iii)** 積み技を+6後も連打しない **(iv)** アンコールに縛られた際の有利不利を更新。これらは「対戦AIの性能が向上する」ことの最小必要条件。相手が1ターンも技を見せていなければ返しの被ダメがゼロだと扱う`battle-engine Phase1`の設計上の穴を**模倣しない**。敵の公開タイプからの合理的STAB候補・見えた攻撃技で**リスク幅**を持たせる。能力P/技/メガ/天候は実戦証拠とShowdown正本を優先。
3. 余力があれば1ターン先の想定相手行動の**同時手 matrix**（技と交代候補の両方）を簡易モジュールとして実装し、`own action` × `plausible enemy action` の損失最大と平均を見せる。通常のターンは同時選択であり、相手が自分の選択を見てから動く従来2plyをそのまま唯一真実と扱わない。簡易投影のダメージ値を正確なBattle結果と偽らない。数値/候補行動を人間向けの表示や研究ログに残す。
4. **公開情報の厳格テスト**：こちらのセットは自分の確定情報、敵は公開6/場に出た種族/確認済み技・特性・HP・状態だけ。敵の実選出3・未公開技・道具・SP・引き先をBotへ渡さない。相手AIも相手から見た公開6だけで判断。仮説は公開事前の候補として記録し、本物の未公開内容を読み取らない。
5. **最小の比較実験**：上記の固定反例(Aグソク+ミミ、BメガルカZ＋ガア／アーキテクト、CリザX/Y＋ガブ)から、少なくとも2つで「旧 vs 新」「合理的/非合理的な敵行動」「選出3体の正しさ」を**分類**し、同seed左右・合法性/技/交代ログで比較。無理に1000戦回さずまず小規模ケースの行動品質を検証。相手を合理的に直したら勝率が下がること自体は問題ない。**実Battle勝数と単体の動作確認を混同しない**。できれば既存 `game(sim,...)` を使用し、新規workflow追加禁止、CI失敗メール連投禁止。
6. ベンチマークの段階的基準：**まず反例のプレミ0件を確認** → 既存BOTで選出率/敵行動が妥当か監査 → 同一条件ペアリング＋勝率/CI（必要な数だけ）→ 人間ランクの再現性を調べる。スコアや勝数だけで合格にしない。上記 source `battle_engine/benchmark.py` の「フェーズごとbaseline gate」の設計が参考。
